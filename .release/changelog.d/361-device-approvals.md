- Device approval keys (#361, MFA design note 6.2/6.3/6.5, D6): migration 128 `device_approval_keys` (one P-256 SPKI per device, registered_via pairing or console_approval, revoked with the device).
- `device.pair.request` takes an optional `approval_key` (base64 SPKI, 91-byte DER), shown as `approval_key_present` in `device.pairing.pending` and registered with the device on approval; `device.pairing.pending` is answered on paired device sessions (approving a new device from a paired one).
- New device-session commands `device.approval.challenge|submit` (ECDSA P-256/SHA-256 over "vh-device-approval-v1" ‖ node_id ‖ server SPKI hash ‖ device SPKI hash ‖ challenge ‖ family ‖ target ‖ expiry; single use, 120 s, bound to session, family and target; keys and device.trust only), `device.approval.request|status` (console approvals, any family, 5 min, at most 3 open and 10/hour per device) and `device.approval.key.register` (device.trust, approved in the console).
- New console commands `auth.approval.list|approve|deny` (a UV passkey assertion only; TOTP and passwords refused) and the push `auth.approval.pending`; refused on device sessions.
- Step-up on device sessions: grants made by the approval key (keys, device.trust) or a console approval (any family) satisfy `auth::stepup::require`; the refusal's `methods` lists `device_approval` / `console_approval`. `email.config.update` is annotated `settings` (it already asked for it through `settings.update`'s save).
- New refusal codes `console_approval_required`, `approval_key_unavailable`, `passkey_required`, `approval_failed` (additive under protocol 1). Audit `device.approval.submit`, `device.approval.key.register`, `auth.approval.request|approve|deny`.
- Shared payload vector `core/test-assets/device/approval-vectors.json` (`tools/dev/device_approval_vectors.py --check`), for vaulthalla-desktop #47/#48; protocol doc `docs/reference/device-approvals.md`.
